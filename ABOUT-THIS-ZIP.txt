SOME PROGRAMS ACT ON A FOLDER WITHOUT BEING ASKED
Some file and folder names make a program run something, or contact another computer,
as soon as the folder is unpacked, shown, entered or opened. The ones that we know of,
and that a project can do without, are renamed or left out (see the lists below).
These are not renamed or left out, so be careful with them:
- Settings such as .idea, .devcontainer, .envrc, mise.toml, .mcp.json and .codex. A
  tool asks whether you trust this folder before it obeys them, and nothing else
  protects you. Say no until you have read the files. Other tools may have such
  settings under names that we do not know of, and some may not ask.
- Build and check files such as build.rs, build.gradle, CMakeLists.txt,
  eslint.config.js, rust-toolchain.toml and .tool-versions. They are the project's
  own. An editor that builds or checks a project as soon as it is opened runs or obeys
  them, and so may a terminal that has a version manager (mise, asdf) or a prompt that
  shows tools' versions.
- Settings that a tool reads from the folder in which you start it, such as .npmrc,
  .yarnrc.yml, .Rprofile and .pdbrc, and, once you make a Git repository of the
  folder, .gitattributes, .gitmodules and .lfsconfig. Some can name a program to run
  or another computer to contact, so read them before you start that tool here.
- Instructions for AI coding assistants, such as CLAUDE.md and AGENTS.md. An assistant
  that you start in this folder follows them as if you had written them.
- On Windows, programs in the current folder. The Command Prompt runs them before the
  program that you meant: with a git.bat in the folder, typing "git" runs that file.

Renamed:
Each file or folder below has "RENAMED-" before its name and ".txt" behind it, and so
has any name that already began with RENAMED-. To find them all, search the unpacked
folder for RENAMED-. A project that needs one does not run until it has its name back.
To give a name back, first look at what is in the file or folder, then remove
"RENAMED-" and ".txt" in your file manager. If it hides the ".txt", let it show file
name extensions first (Windows: in Explorer's View menu; Mac: in Finder's settings,
under Advanced). If it asks whether to change or remove the ending, let it. On a Mac,
Finder accepts a name that begins with a dot only while it shows hidden files (press
Cmd+Shift+.). On Linux such a name is hidden once it is given back (Ctrl+H shows it).
Do not do it in a terminal: a terminal can run what a name holds, whatever quotes you
put round it.
The renaming takes nothing away, but what the lists "Left out on purpose" and "Also
missing" leave out is missing inside a renamed folder too. Capitals and small letters
count alike, and dots and spaces at the end of a name do not count.
A name that only looks like one below is renamed too, because some programs read it as
that name: with accents, with wide letters, or with letters of another alphabet (Greek
or Cyrillic, say) in place of its own. So is a name that an old Windows program could
turn into one below: COM with a Persian digit behind it could become COM1. This
catches some ordinary names too: the German Nuß could become NUL. It does not catch
every case, so be careful with names in other letters. The same goes for names that
look like .git or HEAD, by which Git knows a repository.
